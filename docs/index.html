Per-session sandbox isolation

Every session gets its own isolated directory and access token. No agent can escape its workspace without explicit admin permission.

Real-time job progress & abort

Stream the active tool, elapsed time, and partial output of any long-running job — and abort a runaway task with a single call. New in v2.2.

Headline feature

Memory that follows your agents everywhere

VibzCode connects with any memory system — and is natively compatible with MemoryZ, the sovereign live-memory substrate built for agents that must never forget.

No more context amnesia. Rules, decisions, credentials, and project history survive across sessions, machines, and engines.

Shared sovereign memory substrate

MemoryZ v3 is the shared memory layer for every VibzCode session — one memory, every engine.

Semantic recall

Retrieve rules, decisions, and documentation by meaning — 768-dim vector recall, plus exact hash lookup.

Tasks & atomic claiming

Hierarchical task trees with atomic claiming coordinate multi-agent swarms — no duplicate work.

Namespace isolation

State is segregated per project — default, vibzcode, enterprise — so nothing leaks between workspaces.

Zero-knowledge encrypted vault

Credentials live in an encrypted vault — never in plain text, never in a memory. Memory-as-attachment injects stored context into session prompts transparently.

How it works

Dashboard to done in four steps

From a single command to a supervised, memory-backed agent swarm.

1

Open the dashboard

Launch with npx vibzcode and manage every session from the web admin.

2

Dispatch via the orchestrator

Send tasks to any engine over MCP, the SDK, an endpoint, or the dashboard.

3

Engines do the work

Agents code in isolated sandboxes while you watch live progress streaming.

4

Memory persists

Everything lands in shared memory — MemoryZ or your own system — ready for the next session.

Command-line options

--port <num>

Set the server port (default: 3333, or $PORT).

--status

Check AI key readiness and configuration without starting the server.

--no-open

Disable auto-opening the browser (useful on remote servers).

--host <ip>

Set the network bind host (default: 0.0.0.0).

The dashboard opens automatically at http://localhost:3333
